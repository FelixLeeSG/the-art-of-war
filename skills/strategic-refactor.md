>
> 「备前则后寡，备后则前寡，备左则右寡，备右则左寡，无所不备，则无所不寡。」 —— 孙子兵法·虚实篇

## Skill 定义

**名称**：strategic-refactor（谋攻）
**触发**：`/strategic-refactor <重构目标/遗留系统/迁移需求>`
**定位**：运用兵法策略，制定大规模重构/迁移的作战方案，确保安全渐进地完成转换。

## 核心兵法原则

### 暗渡陈仓 — Feature Flag 渐进迁移
「示之以动，利其静而有主，益动而巽」—— 明面上维护旧系统正常运转，暗地里逐步切换到新实现。

**应用**：
- 用 Feature Flag 控制新旧代码路径
- 灰度发布，逐步扩大新代码的流量
- 旧代码保持可回退，直到新代码完全验证

### 借尸还魂 — 遗留代码现代化
「有用者不可借，不能用者求借。借不能用者而用之」—— 保留旧接口（尸），注入新实现（魂）。

**应用**：
- 保持外部 API 不变，内部重写实现
- Adapter/Facade 模式包装遗留代码
- 渐进替换，一次只换一个内脏

### 金蝉脱壳 — 零停机迁移
「存其形，完其势，友不疑，敌不动」—— 外壳不变，内核已换。

**应用**：
- 蓝绿部署、金丝雀发布
- 数据库双写迁移
- 流量镜像验证

### 偷梁换柱 — 依赖注入替换
「频更其阵，抽其劲旅，待其自败」—— 逐步替换关键组件。

**应用**：
- 通过依赖注入替换核心实现
- 接口不变，实现可热替换
- 逐个组件替换而非大爆炸重写

## 重构策略矩阵

根据风险和规模选择策略：

```
          低风险              高风险
小规模  │ 直接修改          │ 借尸还魂（Adapter 包装）
        │ 快刀斩乱麻        │ 保留接口，替换内部
        │                   │
大规模  │ 暗渡陈仓           │ 金蝉脱壳 + 偷梁换柱
        │ Feature Flag 渐进  │ 完整迁移方案 + 回滚计划
```

## 工作流程

```
输入：重构目标/遗留系统描述

第一步：侦察现状（知彼）
  - 现有代码结构分析
  - 依赖关系图谱
  - 外部接口/API 契约
  - 测试覆盖现状

第二步：评估战局
  - 规模：影响范围有多大？
  - 风险：失败的代价是什么？
  - 约束：不可变的接口/契约是什么？
  - 资源：可用时间和人力

第三步：选择策略
  根据战局选择合适的计策组合

第四步：制定作战计划
  - 分阶段执行方案
  - 每阶段的验证标准
  - 回滚方案
  - 并行开发策略

第五步：执行与验证
  - 每步都有检查点
  - 持续运行旧系统测试确保兼容
  - 渐进切换流量/使用者

输出：分阶段重构作战方案
```

## 反面教训：攻城之害

> 「攻城之法为不得已。修橹轒辒，具器械，三月而后成。」

大爆炸重写（Big Bang Rewrite）= 攻城 = 最下策：
- ❌ 周期长、风险大
- ❌ 无法渐进验证
- ❌ 新旧系统并行维护成本高
- ❌ 容易半途而废

始终优先选择「伐谋」（不改也能解决）或「伐交」（最小改动），避免「攻城」。
