# /retreat-plan — 走计：回滚与止损方案

> 「全师避敌，左次无咎，未失常也。」 —— 三十六计·走为上计
>
> 「善败者不亡。」 —— 孙子兵法

## Skill 定义

**名称**：retreat-plan（走计）
**触发**：`/retreat-plan <部署/迁移/发布/变更>`
**定位**：在执行高风险操作前，像老将安排退路一样，预先制定完整的回滚和止损方案。

## 核心兵法原则

### 走为上计 — 果断撤退
「全师避敌」—— 当情况不对时，最好的策略是快速撤退保全实力，而非死守失败的方案。

**应用**：战略性回滚不是失败，是智慧。

### 空城计 — 优雅降级
「虚者虚之，疑中生疑」—— 资源不足时，以简洁优雅的方式应对，不暴露内部问题。

**应用**：系统部分故障时，展示降级页面而非崩溃错误。

### 李代桃僵 — 牺牲次要保核心
「必以全争于天下」—— 牺牲非核心功能来保障核心服务稳定。

**应用**：优雅降级方案，按优先级逐级关闭功能。

### 金蝉脱壳 — 安全切换
「存其形，完其势」—— 保持外部正常的同时完成内部切换。

**应用**：零停机回滚，用户无感知。

## 工作流程

```
输入：即将执行的高风险操作描述

第一步：评估战局（知己知彼）
  - 操作影响范围有多大？
  - 失败的最坏后果是什么？
  - 有哪些不可逆的操作？

第二步：设置检查点（行军之法）
  - 在每个关键步骤前设置快照/备份
  - 定义每步的成功/失败判定标准
  - 确定「不可撤回点」在哪里

第三步：制定退路（三十六计）
  - 每一步的回滚操作
  - 降级方案（从全功能到最低可用）
  - 数据恢复方案

第四步：定义止损线
  - 什么指标触发回滚？
  - 谁有权决定回滚？
  - 回滚的最长等待时间？

第五步：演练验证
  - 在非生产环境演练回滚
  - 验证备份可恢复
  - 确认回滚脚本可执行

输出：完整的回滚止损方案
```

## 降级梯度（李代桃僵之法）

```
Level 0: 🟢 全功能运行
  ↓ 触发条件：[定义]
Level 1: 🟡 关闭非核心功能
  例：关闭推荐、搜索建议、动画效果
  ↓ 触发条件：[定义]
Level 2: 🟠 只读模式
  例：可浏览但不可下单、可查看但不可编辑
  ↓ 触发条件：[定义]
Level 3: 🔴 静态页面
  例：展示维护公告、缓存的静态内容
  ↓ 触发条件：[定义]
Level 4: ⬛ 完全下线
  展示简洁维护页 + 预计恢复时间
```

## 关键原则

> **宁可备而不用，不可用而无备。**

1. **每次部署前必有退路** — 没有回滚方案的部署 = 无退路的进攻
2. **回滚优先于修复** — 生产环境出问题，先回滚再排查，不要在线修
3. **演练即实战** — 回滚方案不演练 = 不存在
4. **止损果断** — 三十六计走为上，犹豫的代价远大于回滚的代价
