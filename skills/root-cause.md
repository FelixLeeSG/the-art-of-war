# /root-cause — 擒王：Bug 根因分析

> 「摧其坚，夺其魁，以解其体。龙战于野，其道穷也。」 —— 三十六计·擒贼擒王
>
> 「不可胜者，守也；可胜者，攻也。」 —— 孙子兵法·军形篇

## Skill 定义

**名称**：root-cause（擒王）
**触发**：`/root-cause <bug 描述/错误信息/异常现象>`
**定位**：像擒贼先擒王一样，穿透表面症状直达问题根源，一击致命。

## 核心兵法原则

### 擒贼擒王 — 直取要害
不要在「贼兵」（表面症状）上浪费精力，直接找到「贼王」（根本原因）。

### 釜底抽薪 — 治本不治标
「不敌其力，而消其势」— 从根源消除问题，而非不断修补症状。

### 调虎离山 — 隔离问题
「待天以困之，用人以诱之」— 将 bug 从复杂环境中引出，在简单环境中分析。

### 九变篇 — 灵活切换策略
「通于九变之利者，知用兵矣」— 一种调试手段不通，立即切换另一种。

## 工作流程

```
输入：Bug 描述/错误信息/异常行为

第一步：观势（行军篇 — 相敌之法）
  - 收集所有症状和错误信息
  - 确定重现条件
  - 记录出现时间线
  → 问：什么变了？什么时候开始的？

第二步：隔离（调虎离山）
  - 缩小范围：二分法定位
  - 剥离环境：最小重现用例
  - 控制变量：逐一排除干扰因素
  → 将 bug 从「山」（复杂系统）引到「野」（简单环境）

第三步：追踪（用间 — 层层深入）
  - 从症状逆向追踪调用链
  - 检查数据流中的变异点
  - 对比正常/异常路径的分歧点
  → 五个「为什么」：不断追问直到根因

第四步：验证（虚实篇 — 确认虚实）
  - 构造假设并验证
  - 确认修复根因后症状消失
  - 检查是否有同类隐患
  → 确认抓到的是「王」不是「卒」

第五步：歼灭（釜底抽薪）
  - 从根源修复，不做绕行
  - 添加防御（测试/断言）
  - 记录根因供后续参考
```

## 五个层次的「为什么」

```
症状：用户登录偶尔失败
  └ 为什么？→ Token 验证返回 false
    └ 为什么？→ Token 中的时间戳与服务器不匹配
      └ 为什么？→ 服务器时钟有 2 秒偏移
        └ 为什么？→ NTP 同步被防火墙阻断
          └ 为什么？→ 最近的安全策略更新封锁了 NTP 端口

根因（王）：防火墙规则变更封锁了 NTP
表面症状（卒）：登录失败
```

## 输出格式

```markdown
## ⚔️ 擒王报告

### 症状描述
[观察到的表面现象]

### 隔离过程
[缩小范围的步骤和发现]

### 根因追踪
[五个为什么的追踪链]

### 根因确认
- 根因：[一句话描述根本原因]
- 验证：[如何确认这是根因]

### 歼灭方案
- 修复：[具体修复方案]
- 防御：[防止复发的措施]
- 同类排查：[是否存在类似隐患]
```

## 调试九变（灵活切换策略）

当一种方法卡住时，参考九变之术切换策略：

| 当前方法 | 若不通 | 切换为 |
|---------|--------|--------|
| 读代码追踪 | 逻辑太复杂 | 加日志/断点运行 |
| 断点调试 | 难以重现 | 分析 git blame 找变更 |
| git bisect | 提交太多 | 对比正常/异常环境差异 |
| 日志分析 | 日志不够 | 写最小重现测试 |
| 单元测试 | 单元没问题 | 集成测试/端到端追踪 |
