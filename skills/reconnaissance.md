## Skill 定义

**名称**：reconnaissance（用间）
**触发**：`/reconnaissance <代码库/模块/问题域>`
**定位**：像派遣间谍一样，对陌生代码库进行系统性的深度侦察，绘制全貌地图。

## 核心兵法原则

### 用间篇 — 五间俱起
孙子列举五种间谍。映射到代码侦察的五个维度：

| 五间 | 原意 | 代码侦察映射 |
|------|------|-------------|
| **因间** | 利用当地人 | 读 README、注释、文档 — 让代码自己说话 |
| **内间** | 收买敌方官员 | 分析 git log、PR 历史 — 让历史告诉你决策原因 |
| **反间** | 反用敌方间谍 | 分析测试用例 — 测试暴露了系统的预期行为 |
| **死间** | 散布假情报 | 做实验性修改观察反应 — 扰动系统看它如何响应 |
| **生间** | 潜入后生还 | 调试运行、断点追踪 — 深入系统内部后带出情报 |

### 虚实篇 — 识别虚实
「兵之形，避实而击虚」— 找到系统的薄弱环节和关键节点。

## 工作流程

```
输入：目标代码库/模块/问题域

第一阶段：外围侦察（因间）
  - 项目结构概览
  - 文档/README 分析
  - 依赖关系图谱
  - 配置文件分析

第二阶段：历史情报（内间）
  - git log 关键提交分析
  - 高频修改文件（热点区域）
  - 关键贡献者识别
  - PR/Issue 中的设计决策

第三阶段：行为分析（反间）
  - 测试用例揭示的预期行为
  - 边界条件覆盖情况
  - 测试覆盖率薄弱区域

第四阶段：拓扑绘制
  - 模块依赖关系图
  - 数据流向图
  - 关键路径标注
  - 虚实标注（薄弱/坚固区域）

输出：侦察报告 + 代码地图
```

## 输出格式

```markdown
## 🔍 侦察报告

### 全局地图
[目录结构 + 模块关系概览]

### 关键阵地
- 核心模块：[列表及简述]
- 入口点：[主要入口]
- 数据流：[关键数据路径]

### 历史情报
- 热点文件：[频繁修改的文件]
- 设计决策：[从 git 历史中发现的关键决策]
- 技术债标记：[TODO/FIXME/HACK 汇总]

### 虚实分析
- 🟢 坚固区域：[测试覆盖好、文档清晰的模块]
- 🔴 薄弱区域：[缺乏测试、复杂度高、文档缺失的模块]
- ⚡ 关键路径：[牵一发而动全身的核心链路]

### 行动建议
[基于侦察结果的下一步建议]
```

## 示例场景

**输入**：`/reconnaissance src/auth/`

**侦察过程**：
1. 外围：发现 auth 模块有 12 个文件，使用 JWT + OAuth2
2. 历史：`token-manager.ts` 在过去 3 个月被修改 47 次 → 热点/不稳定区域
3. 行为：OAuth2 流程测试覆盖 85%，但 token 刷新逻辑零测试 → **虚**
4. 结论：token 刷新是最大风险点，建议优先加固
