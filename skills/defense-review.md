# /defense-review — 军形：防御性架构审查

> 「昔之善战者，先为不可胜，以待敌之可胜。不可胜在己，可胜在敌。」 —— 孙子兵法·军形篇
>
> 「善守者，藏于九地之下；善攻者，动于九天之上。故能自保而全胜也。」 —— 孙子兵法·军形篇

## Skill 定义

**名称**：defense-review（军形）
**触发**：`/defense-review <代码/模块/系统>`
**定位**：像构筑城防一样审查代码的防御性，确保系统「先为不可胜」。

## 核心兵法原则

### 军形篇 — 先立于不败之地
「善战者，立于不败之地，而不失敌之败也」—— 先确保自己不会崩，再考虑进攻性功能。

### 笑里藏刀 — 输入验证
「信而安之，阴以图之」—— 对外接口看似友好开放，内部严格验证每一个输入。

### 关门捉贼 — 沙箱隔离
「小敌困之，剥，不利有攸往」—— 将不可信的操作限制在安全边界内。

### 反间计 — 安全加固
「因其所使，使为己用」—— 利用攻击者的思路来加固防御。

## 审查维度（九地防御）

```
┌─────────────────────────────────────────┐
│           第一层：边界防御               │
│  输入验证 · 认证授权 · 速率限制          │
├─────────────────────────────────────────┤
│           第二层：数据防御               │
│  SQL注入 · XSS · 序列化安全 · 加密存储   │
├─────────────────────────────────────────┤
│           第三层：逻辑防御               │
│  竞态条件 · 整数溢出 · 空指针 · 异常处理  │
├─────────────────────────────────────────┤
│           第四层：依赖防御               │
│  供应链安全 · 版本锁定 · 漏洞扫描        │
├─────────────────────────────────────────┤
│           第五层：韧性防御               │
│  超时 · 重试 · 熔断 · 降级 · 限流        │
└─────────────────────────────────────────┘
```

## 工作流程

```
输入：待审查的代码/模块/系统

第一步：绘制攻击面（虚实篇 — 找虚）
  - 识别所有外部输入点
  - 标注信任边界
  - 列出敏感操作和数据

第二步：边界审查（笑里藏刀）
  - 所有外部输入是否有验证？
  - 认证/授权是否完整？
  - API 是否有速率限制？

第三步：数据安全审查
  - SQL 查询是否参数化？
  - 输出是否转义？
  - 敏感数据是否加密？
  - 日志中是否泄露敏感信息？

第四步：逻辑安全审查
  - 异常处理是否完善？
  - 是否有竞态条件风险？
  - 边界值是否正确处理？

第五步：韧性审查（九地篇 — 死地求生）
  - 外部依赖故障时的行为？
  - 是否有超时设置？
  - 是否有熔断/降级机制？

第六步：依赖审查
  - 依赖是否有已知漏洞？
  - 版本是否锁定？
  - 是否有不必要的依赖？

输出：防御审查报告
```

## OWASP Top 10 × 兵法映射

| 漏洞 | 对应计策 | 防御要点 |
|------|---------|---------|
| 注入 | 笑里藏刀防御 | 参数化查询，不信任任何输入 |
| 认证缺陷 | 关门捉贼 | 限制范围，严格验证身份 |
| 敏感数据泄露 | 金蝉脱壳 | 数据脱敏，加密传输 |
| XXE | 釜底抽薪 | 禁用外部实体，从根源消除 |
| 访问控制 | 反客为主防御 | 默认拒绝，显式授权 |
| 安全配置错误 | 以逸待劳 | 安全默认配置，减少暴露面 |
| XSS | 李代桃僵 | 输出编码替代原始输出 |
| 反序列化 | 调虎离山 | 隔离反序列化在沙箱中 |
| 组件漏洞 | 远交近攻 | 关键组件自建，边缘可外包 |
| 日志不足 | 隔岸观火升级 | 从被动观察到主动监控 |
